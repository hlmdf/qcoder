# QR Reader

一个透明取景框，拖到屏幕上的二维码上，自动读出里面的链接。

用于「网页上出现一个二维码，但不想掏手机扫」的场景。

## 两种用法

**直接用 exe**：双击 `dist\QRReader.exe`。不用装 Python，不用装依赖，绿色单文件。
代价是启动慢约 3 秒（PyInstaller 单文件要先把自己解压到临时目录）。

**从源码跑**：双击 `install.cmd` 装一次依赖，以后双击 `start.cmd`（不弹控制台，
启动不到 1 秒）。出问题双击 `debug.cmd`，带控制台跑，报错能看见。

## 操作

| 动作 | 效果 |
| --- | --- |
| 拖动框内**任意位置** | 移动 |
| 拖动四边 / 四角 | 缩放（光标会变成双向箭头） |
| 停住约 0.2 秒 | 自动识别 |
| 拖动一下再放下 | 重新开始扫描（同一个码也会再识别一次） |
| 双击 | 立即重新识别 |
| 右键 | 菜单：复制 / 重新识别 / 放大缩小 / 最小化 / 退出 |
| 右上角 − | 最小化到任务栏 |
| 右上角 ✕ | 退出 |
| Esc | 退出 |

识别成功边框闪绿、扫光停下，旁边弹出结果条：可复制、可直接用浏览器打开。

结果条**跟着框走**，位置按框在屏幕上的位置自动选：右边有地方就放右边，不够就放
左边，再不够放下面、上面。框拖到屏幕边上时会自动换边。

程序只允许开一个实例。

## 能做什么、不能做什么

**能**：读出二维码里的文本，通常是网址。扫码跳网页、扫码看文档、扫码加群都行。
码比框小很多也能认（实测小到框的 8% 还能读），不用把框缩到刚好盖住码。

**不能**：微信 / 支付宝的**登录**二维码。那类码要求手机 App 带着登录态去扫，
读出文本没有任何用处。这一点无法绕过。

**框不能比码小**：码被框切掉一部分就没法解，这是二维码的冗余机制决定的。
遇到大码就把框拉大。

## 实现里几个关键决定

**框内填了一层 alpha=1 的白。** 这层肉眼看不见，但必须有。Windows 的分层窗口
会把鼠标事件从完全透明的像素透给下面的程序——不填这一层，框中间就点不动，
只能抓住边框拖。

**扫描跑在工作线程里。** 抓屏 18ms + 解码 15ms，如果跑在界面线程上，动效每 200ms
就卡一下，看起来一顿一顿。现在用 `QThreadPool`（只留一个线程，因为抓屏缓冲是复用
的），结果通过信号回主线程。实测动效帧间隔平均 16.0ms、最大 21.7ms，不再有卡顿。

**动效 60fps，每帧只重绘取景区。** 顶栏和按钮不用每帧重画。代价是 CPU：单核约
13%（整机 0.8%）——这是流程度换来的，受不了可以把 `ANIM_MS` 调到 25。

**用 GDI 的 BitBlt 抓屏，不用 Qt 的 `grabWindow`。** Qt 抓整屏再裁，实测 84ms
一次；BitBlt 只取需要的那块，16ms。而且这 16ms 是固定的，跟面积无关（64×64 和
900×900 都是 16.6ms）——从桌面 DC 取画面要等一次 DWM 合成，正好一帧。所以省电
只能靠降频：刚放下框 200ms 一次，3.5 秒后降到 650ms，已识别后 900ms。

**用窗口句柄的物理坐标（`GetWindowRect`），不做逻辑坐标换算。** 高 DPI、分数缩放、
多显示器一次性绕开。这台机器 250% 缩放，逻辑 260 的框物理上是 650。

**分块搜索解决「框必须和码差不多大」。** `QRCodeDetector` 在二维码只占画面一小块
时连定位都失败（`detect()` 直接返回 False）。把画面切成互相重叠的小块，每块单独
解码，小码在块里就重新占满了。每次扫描只翻 1–2 块、按顺序轮转，保证每帧开销有
上限：实测整帧只认到 22%，分块能认到 8%。单块上限 460px，因为实测大图的检测耗时
会飙到上百毫秒。

**扫光的透明度压得很低（峰值 44）。** 扫光画在码上面，而截屏会把这一层一起抓进
去——带子太重就等于给二维码抹了道亮条。用 12 个动画相位压测过，现在的值 12/12
全中。

**解码前压到长边 420。** 250% 缩放下 600×600 直接解要 29ms，压到 420 之后 14ms。

**兜底预处理只用 1.5x LANCZOS。** 实测 2x 放大和 Otsu 二值化在四种取景框下各有
一半失手，1.5x 全中。

**不做「连续两次一致才算数」。** 解码是确定性的，同一张图读两遍必然一样，这个
校验筛不掉任何东西；反而会把分块轮转的命中判废——第 1 次扫到第 3 块、第 2 次已经
转到第 5 块，中间的空结果直接把候选清掉了。改成只过滤不可打印字符。

## 自测

`test_qr.py` 直接调用主程序的 `decode_gray` / `tile_rects`，测的就是实际跑的代码：

```bash
.venv/Scripts/python.exe test_qr.py
```

- 24 个基础用例：4 种内容（纯网址、长网址、中文前缀、纯中文）× 4 种尺寸，
  外加高 DPI 下的 600/750 物理像素取景框
- 10 个尺寸容差用例：码占框 40% 一路到 8%
- 半张码必须识别失败

当前结果：24/24 直接命中，容差 10/10，半张码正确拒绝。

端到端自检（会弹窗，把取景框盖到二维码上真实抓屏解码，顺带报耗时）：

```bash
.venv/Scripts/python.exe main.py --selftest
```

## 自己打包

双击 `build.cmd`，或：

```bash
.venv/Scripts/python.exe -m PyInstaller --noconfirm --clean --onefile --noconsole --name QRReader main.py
```

产物 `dist\QRReader.exe`，约 90MB（主要是 Qt）。

- 单文件启动慢约 3 秒（要解压）。想要秒开就换成 `--onedir`，产出一个文件夹，
  启动不到 1 秒，但不再是单个文件。
- 打包后已确认 DPI 感知正常：250% 缩放下抓取区域仍是 650×650 物理像素，识别正常。

## 已知取舍

- 只认 **QR 码**，不认条形码、Aztec、PDF417。
- 只处理静止画面，不做连拍跟踪。
- 不记录历史，要留的链接自己复制走。
- 抓屏用 Windows 的 GDI BitBlt，程序面向 Windows。
- 屏幕静止且已过 3.5 秒的「积极期」后，只用最省的一遍算法扫。此时如果页面在框
  下面变了，拖动一下或双击即可重新识别。
